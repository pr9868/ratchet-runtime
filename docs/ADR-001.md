# ADR-001: Use a local POSIX coordinator for the reference runtime

**Status:** Accepted

**Date:** 2026-08-21

**Decider:** Pradeep Kaushik

## Context

Ratchet Runtime needs to serialize lock inspection, stale seizure, fencing-token allocation, lock
publication, and runner-state mutation. The public reference implementation is intentionally a
small, dependency-free Python module for one host and one local state directory. It must work on
macOS and Linux, expose state as inspectable files, and fail closed when ownership is uncertain.

Atomic file replacement prevents torn JSON but does not make a multi-file read-modify-write sequence
linearizable. The earlier design proved this when two stale-lock breakers allocated the same fencing
token before either published ownership.

## Decision

Use a persistent `.tenure.guard` file protected by POSIX `flock` as the local coordinator. Hold that
guard while inspecting ownership, allocating the next fencing token, publishing a new lock, and
performing every tenure-protected runner-state mutation. Continue using temp-file write, file fsync,
atomic replace, and directory fsync for durable JSON publication.

This decision applies only to local POSIX filesystems. It is not presented as a distributed lease.

## Options considered

| Option | Complexity | Dependencies | Correctness boundary | Assessment |
|---|---:|---:|---|---|
| `exists()` plus lock-file write | Low | None | Check and write race | Rejected |
| `O_EXCL` lock creation | Low | None | Serializes creation, but not stale seizure plus counter allocation | Rejected |
| POSIX `flock` coordinator | Low | Standard library | One host and conforming local POSIX filesystem | Accepted |
| SQLite transaction | Medium | Standard library | Strong local transaction boundary with a less inspectable state model | Viable future option |
| Distributed lease/CAS service | High | External service | Multi-host coordination if configured and operated correctly | Required for distributed scope |

## Trade-offs

The accepted design preserves the small flat-file runtime and makes the critical ownership sequence
serializable. It also limits portability: Windows and network filesystems are outside the reference
claim, and a process with the same OS identity can still replace the guard or state files. A separate
identity or mediated API remains necessary for untrusted callbacks.

The fencing token must still reach target systems. Local serialization prevents two Ratchet runners
from mutating the same state concurrently; it cannot stop a delayed external write unless the target
also rejects older tokens.

## Consequences

- The reference package supports Python 3.9+ on macOS and Linux with local POSIX storage.
- Every state root represents one workflow and one coordination domain.
- Network filesystems and multi-host execution require a different coordinator implementation.
- Completion remains one atomic record, while breaker and per-run records are separate durable
  files rather than one cross-file transaction.
- The conformance suite must continue to race fresh acquisition and stale seizure across real
  processes.

## Follow-up triggers

Revisit this decision if the public runtime needs Windows support, multi-host execution, an untrusted
same-user callback, or atomic transactions spanning completion, breaker, and run-history records.
